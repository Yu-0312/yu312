It lets your AI agent reverse-engineer apps and web pages whose source code you can't get, and then recreate their features in your own project based on the analysis

Personally, I think that if AI agents become strong enough in the future, this project will actually turn into a burden: every call needs a lot of tools, and the results also have to be returned and recreated through the tools it sets up, so once models are strong enough it will lose its purpose

It's still a real threat to paid apps for now, but that doesn't mean it can restore the original source code in one click, nor that it can automatically copy an entire commercial software product

## DeUA_xbEyKf
💥 Zhejiang University open-sources nanoMuse: a personal AI agent with memory that can operate your devices!

When I saw the nanoMuse project recently, I thought it looked a lot like Meta's recent Muse — I never expected an open-source challenger to Muse would show up!

nanoMuse is an open-source personal agent, focused on cross-device collaboration, tool calling, computer operation, and authorization for high-risk actions

GitHub: https://github.com/nano-muse/nano
Website: https://nanomuse.cn
Paper: https://arxiv.org/abs/2610.08699

Here are the technical highlights most worth studying 👇

1️⃣ Chatbots are done — it's time to build a complete Agent system

A typical Chatbot workflow is simple: you enter a question → the model generates an answer → the conversation ends
An Agent is different: understand the goal → decide the next step → call tools → observe the results (and revise the original plan if necessary)

For example, if you tell it: "Help me organize the research papers on my desktop, categorize them by topic, and then generate a summary."
An Agent with the right tools would theoretically need to:
scan the desktop to get a file list → read the papers and identify their research topics → create category folders and organize the files → generate a summary

So the truly difficult part is making sure it can actually complete the task, and handle errors correctly when they occur

2️⃣ Cross-device collaboration: give commands from your phone, let your computer do the work

This is one of nanoMuse's most appealing designs. But then a question arises: my Claude and Codex can already take commands from my phone and work — so what makes nanoMuse special?

nanoMuse's difference isn't "letting AI write code from your phone" — it's trying to integrate different devices and existing Agents into a collaborative system

nanoMuse's design gives phones and computers their own Agents and tools, which can delegate work to each other through a Hub. This doesn't mean a phone can control all devices unconditionally: the computer must be online, the relevant programs must be running properly, and operation permissions, network, and OS limitations all affect what's actually possible.

3️⃣ Apps without APIs can also be operated through the screen!

This is a very important direction for AI Agents. Traditional automation usually relies on APIs, but what if the target app has no API?

nanoMuse's design uses a multi-layer tool strategy:
🔹 Skills / CLI: prefer existing skills and command-line tools
🔹 MCP: integrate external tools and services through a standardized interface
🔹 Browser Automation: operate web pages, read content, fill out forms
🔹 GUI / Computer Use: when necessary, use screen visuals, recognition, and clicks
btw: being able to operate a GUI doesn't mean being able to perfectly operate every app — screen changes, pop-ups, login states, permissions, and OS limitations can all cause automation to fail. A truly ideal Agent should still prioritize stable APIs and only fall back to visual operation when there's no better interface

4️⃣ Let AI remember you

Many people think AI remembers them because the model has actually learned their personal information, but in reality model parameters, chat history, and external memory are different things

nanoMuse emphasizes readable, editable Markdown memory, and provides modules for memory storage, organization, and vector embedding in the project

The memory files listed in the official documentation include:
📄 SOUL.md: the Agent's identity, principles, and behavior settings
📄 USER.md: user information and preferences
📄 MEMORY.md: important memories
📄 HEARTBEAT.md: settings for periodic wake-ups and routine tasks

But outdated information, incorrect summaries, duplicate records, and synchronization across different devices are still issues that need to be handled

📌 What has been confirmed? What is still marketing?

Open source doesn't mean the features are mature, and having code doesn't mean it has passed a complete security audit; likewise, having an Agent that can operate a computer doesn't mean it can reliably complete all complex work.

## DeOA-ahk0W5
🚨 Big news! Google is getting the whole world to help "catch AI"!
Google just announced that SynthID Detector is now open globally
You can now drop in an image, video, or audio file and check whether it was generated by AI
And this time it's not just Google's own models — OpenAI, NVIDIA, and Kakao have joined the collaboration, and Apple will be joining soon. The core technology is an invisible AI watermark: after the Detector scans the content, it can tell whether it carries a SynthID watermark.

Even more striking, Google has already watermarked more than 180 billion images and videos!
Very often you simply can't tell whether something is AI-generated or AI-edited — now the content itself carries its own ID card, which is hugely significant!

👉 Official introduction to Google SynthID Detector: https://blog.google/innovation-and-ai/models-and-research/google-deepmind/synth-id-ai-content/?utm_source=chatgpt.com
